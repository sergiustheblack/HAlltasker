# HAlltasker

Язык: Русский | [English](README.en.md)

Custom integration для Home Assistant: двусторонняя синхронизация задач между любыми сущностями `todo.*`. Через штатные интеграции HA это связывает iCloud Reminders (CalDAV), Google Tasks, Яндекс Календарь (CalDAV) и локальные списки.

Статус: в разработке, MVP не выпущен.

- Требования: [docs/ru/SPEC.md](docs/ru/SPEC.md)
- Архитектура: [docs/ru/ARCHITECTURE.md](docs/ru/ARCHITECTURE.md)
- Задачи (только на английском): [docs/TASKS.md](docs/TASKS.md)
- Исследование и ограничения внешних систем: [docs/ru/RESEARCH.md](docs/ru/RESEARCH.md)

## Установка через HACS

1. HACS → ⋮ (три точки) → **Custom repositories**.
2. Добавьте репозиторий `s-parfyenov/HAlltasker`, категория **Integration**.
3. Найдите **HAlltasker** в HACS и установите.
4. Перезапустите Home Assistant.

Интеграция не содержит собственных зависимостей: используются только штатные возможности HA.

## Подключение внешних систем

Все внешние списки подключаются штатными интеграциям HA и становятся обычными сущностями `todo.*`. HAlltasker работает с ними одинаково.

### Яндекс Календарь (экспериментально)

1. Получите пароль приложения: Яндекс ID → Безопасность → Пароли приложений → **Календарь** (CalDAV).
2. Добавьте в HA интеграцию **CalDAV**: URL `https://caldav.yandex.ru`, логин — полный адрес `LOGIN@yandex.ru`, пароль — пароль приложения.
3. Дождитесь появления сущностей `todo.*` для списков дел (`todos-*`).

Особенности:

- Штатная интеграция CalDAV обновляется примерно раз в 15 минут; уменьшение интервала пары в HAlltasker не ускоряет внешнюю интеграцию.
- Список дел («Алиса, добавь в список дел…») доступен как обычные задачи CalDAV (дата без времени).
- Напоминания Алисы с точным временем — экспериментальный сценарий; публичного API напоминаний нет (см. [docs/ru/RESEARCH.md](docs/ru/RESEARCH.md) и [docs/LINK_CHECK.md](docs/LINK_CHECK.md)).
- Список покупок Алисы не поддерживается.

### iCloud Reminders

1. Создайте пароль приложения на сайте Apple (appleid.apple.com → Учётная запись → Пароли приложений).
2. Добавьте в HA интеграцию **CalDAV**: URL `https://caldav.icloud.com`, логин — Apple ID, пароль — пароль приложения.
3. На iPhone подключите iCloud как отдельный аккаунт CalDAV (Настройки → Календарь → Учетные записи → Добавить → Другое → CalDAV): тогда списки появятся в Reminders как «сторонние», без тегов и умных списков.

Важно: «обновлённые» (upgraded) списки Reminders хранятся в частном хранилище Apple и через CalDAV не видны. Используйте списки, которые не были перенесены в новый формат.

### Google Tasks

Добавьте штатную интеграцию **Google Tasks**. Ограничение API: время в дате выполнения не сохраняется — только дата. HAlltasker понижает `datetime` до `date` автоматически, это не конфликт.

### Local To-do и Список покупок

Работают как обычные `todo.*`. У Списка покупок нет даты выполнения и описания — эти поля просто не синхронизируются для него.

## Настройка

Только YAML, в `configuration.yaml`. Применить изменения конфигурации в текущей сборке можно только перезапуском HA (`homeassistant.reload_config_entry` не перечитывает YAML; сервис `halltasker.reload` — в работе).

```yaml
halltasker:
  pairs:
    - id: yandex_to_icloud          # обязателен, уникален, [a-z0-9_]+
      a: todo.yandex_dela           # обязателен, сущность домена todo
      b: todo.icloud_reminders      # обязателен
      interval: 60                  # секунды, >= 15, по умолчанию 60
      conflict: prefer_a            # prefer_a | prefer_b (по умолчанию prefer_a)
      initial_sync: merge           # merge | dry_run (по умолчанию merge)
      enabled: true                 # по умолчанию true
      a_to_b:                       # все ключи необязательны
        create: true
        update: true
        complete: true
        delete: true                # true | false | soft
        filter:
          title_regex: "^(?!#).*"   # валидный regex
          require_due: false
        transform:
          due: keep                 # keep | date_only | drop
          title_prefix: ""
      b_to_a: {}
```

Пары можно указывать сколько угодно. Одна сущность в нескольких парах (например, Яндекс ↔ iCloud и Яндекс ↔ Google) — в работе (архитектура v1.1, задачи T-22+); в текущей сборке это не поддерживается.

## Сервисы

| Сервис | Параметры | Описание |
|---|---|---|
| `halltasker.sync_now` | `pair_id` (необязательно) | Немедленный цикл синхронизации одной пары или всех. |
| `halltasker.dry_run` | `pair_id` (необязательно) | Возвращает запланированные действия без записи (ответ сервиса: `{"pairs": {pair_id: [действия]}}`). |

## Сенсоры

Для каждой пары создаётся `sensor.halltasker_<id_пары>`:

- состояние: `ok` | `error` | `dry_run` | `disabled`;
- атрибуты: `last_run`, `links`, `last_error`, `last_actions` (счётчики по типам), `planned_actions` (в режиме dry_run).

## Как это работает

- Связи между задачами хранятся только во внутреннем хранилище HA (`.storage/halltasker`). В ваши задачи ничего не дописывается: ни префиксов, ни скрытых полей.
- Политика конфликтов — на пару: `prefer_a` или `prefer_b`. Изменения разных полей с двух сторон сливаются; время последнего изменения у задач в HA нет, поэтому «настоящий» last-write-wins невозможен.
- Удаление: `true` — удалить на другой стороне; `soft` — отметить выполненной; `false` — не трогать и не создавать заново. Память об удалениях (tombstone) хранится минимум 30 дней.
- Повторный цикл без внешних изменений не делает ни одной записи.

## Ограничения

- Повторяющиеся задачи (RRULE), подзадачи, вложения, теги, приоритеты — не поддерживаются.
- Google Tasks: только дата, без времени.
- CalDAV-интеграции обновляются примерно раз в 15 минут.
- Настройка через UI отсутствует; источник конфигурации — YAML.
- Диагностика (скачивается со страницы интеграции) не содержит секретов по построению.
